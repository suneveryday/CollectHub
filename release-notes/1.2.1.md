# CollectHub v1.2.1

本版本修复了安装版 CollectHub 无法抓取小红书内容的问题。

## 问题原因

CollectHub 1.2.0 从源码运行时可以找到 `scripts/xhs_downloader_bridge.py`，但安装为 wheel 后，`xhs_adapter` 仍按源码目录结构计算 bridge 路径。正式 CLI 因此启动了不存在的脚本，子进程没有返回 JSON，最终被误报为 `invalid_parser_output`。

这不是 XHS-Downloader 2.7 失效，也不需要通过升级到 2.8 beta 解决。

## 修复内容

- 将 XHS bridge 纳入 `content_ingestor` Python 包，确保源码与 wheel 安装使用同一实现。
- 保留原有 `scripts/xhs_downloader_bridge.py` 入口作为兼容包装。
- 安装不完整时返回明确的修复提示，不再将缺失 bridge 混淆为上游 JSON 解析失败。
- 增加 wheel 安装路径回归测试，防止发布包再次遗漏 bridge。
- Release workflow 支持读取版本专属更新说明。

## 验证

- 82 项自动化测试通过。
- wheel 构建产物已确认包含 `content_ingestor/xhs_downloader_bridge.py`。
- 使用真实 `xhslink.com/m/...` 分享链接完成端到端验证：正文与 13 张图片保存成功。
- 重复抓取返回 `already_saved`，幂等行为正常。
- `content-ingestor doctor` 全部通过。

## 升级

```bash
curl -fsSL https://raw.githubusercontent.com/suneveryday/CollectHub/v1.2.1/install.sh | sh -s -- --yes
```

本次升级不会修改已保存的 `~/CollectHub` 内容库。
